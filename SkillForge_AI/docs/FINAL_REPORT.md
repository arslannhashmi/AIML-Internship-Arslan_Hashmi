# SkillForge AI — Final Report

## Executive summary

SkillForge AI is a deterministic resume-skill extraction and career-reasoning
pipeline. It converts a PDF resume into a structured profile, compares that
profile with a curated set of technology careers, calculates proficiency gaps,
and produces a prerequisite-aware learning path. The current API and static
frontend are implemented and live-tested.

The project intentionally favors traceability over claims of broad model
performance. The knowledge base is hand-curated, the resume corpus is
synthetic, Phase 6 weak labels come from the dictionary matcher, and Phase 9
is face-validity testing rather than accuracy evaluation.

## Scope and architecture

The implemented scope covers Phases 3–14:

- Phases 3–5 build the database, resume parser, and deterministic dictionary
  extractor.
- Phase 6 evaluates spaCy EntityRuler and DistilBERT NER against held-out
  synthetic resumes.
- Phases 7–8 add deterministic normalization, threshold calibration, and an
  in-memory NetworkX prerequisite graph.
- Phases 9–11 implement weighted career matching, gap arithmetic, and
  prerequisite-safe learning paths.
- Phase 12 wraps those stages in a JSON-serializable orchestrator.
- Phase 13's LLM layer is omitted by design.
- Phase 14 exposes the pipeline through FastAPI and serves the static
  HTML/CSS/vanilla-JavaScript interaction surface.

See [SYSTEM_ARCHITECTURE.md](SYSTEM_ARCHITECTURE.md) for the Mermaid
architecture, pipeline, ERD, and module tree.

## Dataset and knowledge-base methodology

The seeded SQLite knowledge base contains the following hand-built resources:

| Resource | Count | Construction |
|---|---:|---|
| Canonical skills | 101 | Hand-curated technology taxonomy |
| Skill aliases | 26 | Hand-curated abbreviations and alternate forms |
| Careers | 15 | Hand-curated role set |
| Prerequisite edges | 62 | Domain-judged learning relationships |
| Career-skill requirements | 116 | Expert-assigned importance and proficiency targets |

Skills were selected from widely used technology taxonomies, including the
LinkedIn Skills taxonomy and Stack Overflow Developer Survey 2023, then
reduced to a scope suitable for one FYP project. Importance, minimum
proficiency, and preferred proficiency are expert-curated 1–5 values rather
than job-posting frequency estimates.

The resume corpus contains three synthetic Phase 4 PDFs and 18 additional
labelled Phase 6 synthetic PDFs:

| Split | Count | Use |
|---|---:|---|
| Training | 14 | Weak-supervision training data |
| Held out | 4 | Skill-level extraction evaluation |

The held-out set contains 39 ground-truth skill mentions. Recommendation
evaluation uses three hand-built profiles:

- Data Science → Data Scientist
- Frontend → Frontend Developer
- DevOps → DevOps Engineer

These are plausibility fixtures, not a representative benchmark.

## Phase 7 — normalization calibration

Source: `skillforge/evaluation/phase7_threshold_calibration.json`.

Normalization follows alias matching, full-string RapidFuzz matching, and a
calibrated semantic fallback. The semantic model is
`sentence-transformers/all-MiniLM-L6-v2`, implemented through raw Transformers
with mean pooling because the wrapper package was unavailable in the package
index.

| Measurement | Value |
|---|---:|
| Positive score minimum | 0.3420 |
| Positive score maximum | 1.0000 |
| Negative score minimum | 0.0673 |
| Negative score maximum | 0.3226 |
| Chosen threshold | 0.3323 |
| Calibration F1 | 1.0000 |

The cutoff was selected by the best F1 over labelled equivalent/different
pairs, not by an arbitrary constant. The small calibration set limits claims
about broad semantic matching.

## Gap analysis and learning path

Gap arithmetic is deterministic:

```text
gap_score = importance × max(preferred_proficiency − current_proficiency, 0)
```

Omitted skills receive current proficiency `0`. Importance and proficiency are
1–5 values, so the maximum gap score is 25. The calibrated presentation bands
are:

| Bucket | Score |
|---|---:|
| Strong | 0 |
| Minor | 1–5 |
| Moderate | 6–10 |
| Major | 11–15 |
| Critical | 16+ |

The learning-path planner applies Kahn topological ordering over the NetworkX
prerequisite graph. Among currently unlocked skills, larger gap scores are
selected first, with skill ID as the deterministic final tie-breaker.

### Coverage versus depth

Career match and gap analysis intentionally measure different axes. The career
match score primarily reflects skill coverage—whether the required skill is
present in the profile—while gap analysis separately measures the proficiency
deficit against the career requirement's preferred level. These measures can
therefore diverge: a learner can have high coverage and a high career match
score while still having meaningful depth gaps because the stored proficiency
does not yet reach the preferred target. This distinction is a documented
product behavior, not a scoring-algorithm change.

## API and deployment

FastAPI exposes health, profile upload, career recommendation, gap, roadmap,
and full-agent routes. The API uses the `db_client` abstraction and
request-scoped connections. The current published deployment is:

<https://skillforgeaitest.replit.app>

The deployment wrapper sets a repository-relative
`SKILLFORGE_DB_PATH` and starts Uvicorn. The basic deployment is appropriate
for a checkpoint and is not a multi-instance production data architecture.

## Limitations and interpretation boundaries

### Synthetic and circular evaluation

The Phase 6 and Phase 7 evaluations are circular by construction: synthetic
resumes and weak labels are generated from the same 101-skill taxonomy and
dictionary matcher used by the pipeline. The ground truth is skill-level,
synthetic, and not token-level annotation from independently labelled real
resumes.

### Deep-learning scope

DistilBERT is the only deep-learning component. It learned weak labels from
the Phase 5 dictionary matcher, so it is not evaluated against an independent
annotation source. The saved metrics must not be presented as real-world model
performance.

### Curated knowledge base

Career requirements, importance weights, proficiency targets, and prerequisite
edges are expert-curated project assumptions. They are not learned from
employment outcomes or a corpus of job advertisements.

### Omitted LLM layer

Phase 13 is permanently omitted by design. There is no prompt-generation
module, LLM client, guardrail layer, API-key dependency, or explanation
fallback. The deterministic Phase 12 structured dictionary is the final
pipeline output.

### Phase 15 scope

The original Phase 15 plan for a separate/full frontend deliverable is omitted
by design. The repository now contains a lightweight static interaction
surface served by FastAPI, but it does not represent the larger deferred
Phase 15 scope.

### Persistence and scaling

The basic deployment uses the checked-in SQLite database abstraction and local
upload path. It is intentionally simple for the FYP checkpoint and is not a
shared multi-instance production architecture. Horizontal scaling would
require a durable shared database and durable upload storage.

### Out of scope

Neo4j, K-Means clustering, the larger multi-agent framework, LLM narration,
real-resume benchmarking, and the deferred full frontend scope remain outside
the accepted project scope.
